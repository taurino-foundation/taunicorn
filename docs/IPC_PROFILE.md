# Rust IPC message profile

Use `profile::Session` when the application needs typed, filtered **messages**, not an arbitrary byte stream. Both peers must agree on the schema. Private endpoints, Secure v2 and this profile are separate controls: private admission checks OS identity and connection capacity; Secure v2 authenticates the configured peer key; the profile controls what the application can send or receive. There is no plaintext fallback. Selecting private transport alone does not filter a single message.

## Opening a session

1. Set up `let (audit, exporter) = Audit::bounded(capacity)?;` and run `exporter.run(append_and_anchor)` on a dedicated thread. Keep an `Audit` clone for health monitoring.
2. Obtain a fresh connection via `Connection::connect_private` or `Server::listen_private` followed by `accept` (or their with-policy equivalents). Do not perform application I/O before `Session::open`.
3. Call `Session::open(connection, role, local_private_key, expected_peer_public_key, limits, audit).await?`. Unlike the underlying Secure v2 server constructor, this takes **local private key first on both roles**. It consumes the entire duplex, verifies that it has a private admission lease, performs the pinned handshake and returns no raw/secure handle. The profile cannot be attached to a split stream. The caller supplies keys; no key discovery, environment lookup, remote service or downgrade takes place.

The pin must be bound to the intended peer by the deployment. If certificate-based identity is required, validate the chain, expiry, revocation, identity binding and purpose in the operator's trust provider, then supply its approved public key. No certificate is carried or verified by this profile, and no qualified identity, signature or seal is asserted. OS denials before the profile sees a connection require independent OS/transport audit.

## Wire contract and policy

Each Secure v2 record carries one complete MessagePack tuple. Schema 1 (status) is exactly `fixarray(3), positive-fixint(1), bool(ready), nil | UTF-8 string(private_note)`. The first two markers must use that encoding. A note, if present, is at most 256 **bytes**, not characters. No extra fields, trailing bytes, maps, nested objects, binary blobs, malformed strings, unknown schema IDs or generic serializers are supported.

`session.send(Status { ready, private_note }).await?` validates note length, constructs the allowlisted projection and encrypts **only** `[1, ready, nil]` (four plaintext bytes). `session.receive().await?` authenticates and decrypts first, validates the entire tuple and returns only the boolean. Notes from compatible peers are never returned or logged. Unsupported inbound messages end the session; invalid local input is rejected before transmission. A boolean is not a general-purpose PII detector. Review and version the schema before admitting other data; this profile says nothing about the privacy of timing or traffic volume.

## Resources and cancellation

| Boundary                | Rule                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Handshakes and sessions | Reuses the core's bounded Secure v2 handshake and the private admission layer's global and per-OS-user leases. The profile does not count claimed identities from messages.                                                                                                                                                                          |
| Application frames      | Secure v2 checks the declared ciphertext length against the smaller of 512 plaintext bytes and the remaining read budget, plus its fixed framing overhead, **before allocating the frame**. Schema validation is stricter than this cap.                                                                                                             |
| Byte quotas             | Independent lifetime plaintext budgets, default 1 MiB each; minimum 4. Read charges the actual frame (including discarded input); write charges the redacted output. A direction with fewer than four bytes left rejects I/O without consuming the opposite budget. No pooled quota across directions.                                               |
| Idle / stalled frame    | Default 30 seconds; configurable positive duration up to 24 hours. One watchdog per live session closes even when the application makes no calls. Successful complete messages refresh session activity. Each active operation also has that duration as an absolute deadline; activity in the opposite direction cannot keep a partial frame alive. |
| Cancellation            | Dropping an active handshake, send or receive closes the session; never replay automatically after uncertain progress. Dropping a future waiting only for its direction's gate does not close it. `close()` and drop terminate both directions. Reconnect and authenticate from scratch.                                                             |

## Audit delivery contract

Events contain a wall-clock timestamp (`SystemTime`, render in UTC), process-local connection number, fixed reason/kind and one-based export order. They contain no endpoint names, paths, OS IDs, keys, payloads or error strings. IDs and sequence numbers restart with their process/exporter; they are not global identities. The exporter preserves queue order rather than sorting by the wall clock.

The bounded channel accepts 1–65,536 events. It **never waits for queue space or disk on the I/O path**. Both start and successful admission must be enqueued: a full or disconnected channel denies entry, including after a successful handshake. Other events are best effort; a stalled/disconnected sink does not block established duplex traffic. `Audit::dropped()` counts unacknowledged events lost to overflow, disconnection, exporter failure or abandonment. Monitor it and `is_disconnected()` out of band and alarm on change. A connected consumer can still be stalled. No event is guaranteed to survive a process crash.

`Exporter::run` invokes the supplied callback in order. Return `Ok(())` only when the protected append and required external integrity anchor have succeeded; return `Err` on storage, rotation or anchor failure. On error the exporter stops, drops its queue and reports a fixed error without backend details. Drop producer handles and close sessions before joining the exporter for orderly drain. **Admission means enqueued, not durably recorded.** If policy requires durable acknowledgement before access, this adapter alone is insufficient. Provision separate access controls and retention, verify external checkpoints and exercise restoration/rotation in deployment. No local hash chain or in-process queue is tamperproof; the library neither provisions a sink nor reports incidents to an authority.

Run `cargo test --locked -p taunicorn --test profile` and repeat with `--features compliance-profile`. Private endpoint tests need the platform's private runtime directory/pipe support. Tests use synthetic data; they are not a production throughput benchmark or certification.
